# gitlab-ci-local Fedora packaging

Fedora RPM packaging for [gitlab-ci-local](https://github.com/firecow/gitlab-ci-local),
a CLI tool that runs GitLab CI pipelines locally.

## Layout

| File | Purpose |
|------|---------|
| `gitlab-ci-local.spec` | The RPM spec |
| `gitlab-ci-local.1` | Man page (Fedora-written; upstream has none) — also in `SOURCES/` as Source2 |
| `node-json-import-attributes.patch` | Patch0: JSON import attributes for plain-Node compatibility (upstreamable) |
| `generate-vendor-tarball.sh` | Regenerates the vendored-dependencies tarball (Source1) |
| `build.sh` | Convenience wrapper around `rpmbuild -ba` |
| `build-srpm-copr.sh` | Builds the dist-neutral SRPM for COPR |
| `rpmlint.conf` | rpmlint filters (false-positive suppressions) |
| `bundled-deps.txt` | Manifest of the npm packages shipped with the application |
| `SOURCES/` | Source0 (upstream tarball), Source1 (vendor tarball), Source2, Source3 |

## How it works

Upstream builds with **bun**, but bun is not in Fedora - and neither is any
usable JavaScript bundler or TypeScript compiler:

- `nodejs-esbuild` exists only in F44/F45 (retired from rawhide)
- `nodejs-typescript` has not been built since Fedora 34

So the package is self-contained:

1. **Source1 (vendor tarball)** - created with upstream's own `bun.lock`
   (same pinned bun version as upstream's release CI), split per the
   [Node.js packaging guidelines](https://docs.fedoraproject.org/en-US/packaging-guidelines/Node_js/):
   - `node_modules_prod/` - the npm packages the application actually loads
     at runtime (the closure computed from an esbuild metafile on the
     packaging machine), installed with the application and declared with
     `Provides: bundled(nodejs-<name>)`
   - `node_modules_dev/` - the TypeScript compiler, a build-only tool that
     is never installed into the RPM
   - regenerate after a version bump with `./generate-vendor-tarball.sh <version>`
2. **%build** - transpiles the TypeScript sources with the vendored `tsc`
   (`noCheck`: the dev-only `@types/*` are not vendored, only the emit is
   needed). Patch0 adds JSON import attributes so the code runs under plain
   Node.js, not only inside bundlers.
3. **%install** - classic nodejs application layout: transpiled `dist/`,
   the runtime `node_modules` tree and `package.json` under
   `/usr/share/gitlab-ci-local`, with a `/usr/bin/gitlab-ci-local` symlink
   (like an `npm install -g`).
4. **Runtime** - `Requires: nodejs >= 20.19` (floor imposed by yargs).
   Jobs with an `image:` run in a container runtime (`Suggests:
   moby-engine`); shell jobs run on the host.

The zsh completion is generated by the binary itself at install time.
`SOURCES/gitlab-ci-local-<version>-bundled-licenses.txt` is the license
inventory of the bundled modules.

## Building

```
sudo dnf install rpm-build git-core nodejs
./build.sh
```

Output: `RPMS/noarch/gitlab-ci-local-<version>-<release>.noarch.rpm` and the
SRPM. The `%check` section runs `--version`, `--help` and parses a minimal
pipeline inside a git repository fixture. (`build.sh` passes `--nodeps`
because it may run on hosts without the BuildRequires installed; in
mock/COPR/koji the deps resolve normally.)

## Installing

```
sudo dnf install ./RPMS/noarch/gitlab-ci-local-*.noarch.rpm
```

## Building in COPR

COPR only auto-downloads `Source`s that have a URL; the local files
(Source1 vendor tarball, Source2 man page, Source3 licenses file) must be
delivered with the build. Upload the **SRPM** - it embeds everything:

```
./build-srpm-copr.sh
copr-cli build <user>/<project> gitlab-ci-local-4.76.1-1.src.rpm
```

The SRPM is dist-neutral (`Release: 1%{?dist}` re-expands per chroot,
giving e.g. `1.fc45`, `1.fc46`). It only build-requires `nodejs` and
`git-core`, so it builds on any current chroot - including rawhide, where
neither esbuild nor a system TypeScript exists.

Note: the spec deliberately uses `Release: 1%{?dist}` instead of
`%autorelease`, because COPR rebuilds uploaded SRPMs with `mock --rebuild`,
which does not run the rpmautospec plugin (it only runs for
`mock --buildsrpm`). Switch back to `%autorelease` when importing into
Fedora dist-git.

## Updating to a new release

```
# update Version: in the spec, then:
./generate-vendor-tarball.sh <new-version>
mv gitlab-ci-local-<new-version>-vendor.tar.xz SOURCES/
mv gitlab-ci-local-<new-version>.tar.gz SOURCES/   # cached download from the script
# refresh the bundled(...) Provides block from the new bundled-deps.txt:
awk -F'\t' '{name=$1; gsub("/","-",name); printf "Provides:       bundled(nodejs-%s) = %s\n", name, $2}' bundled-deps.txt
# regenerate the licenses inventory (Source3)
awk -F'\t' '{print $1"\t"$2"\t"$3}' bundled-deps.txt > SOURCES/gitlab-ci-local-<new-version>-bundled-licenses.txt
# (keep the three header comment lines of the existing file)
./build.sh
```

## Known issues

- Rendering the `--help` table uses `Intl.Segmenter` (via `string-width`),
  and nodejs **segfaults without the full ICU data** installed
  ([RHBZ #2548696](https://bugzilla.redhat.com/show_bug.cgi?id=2548696),
  filed for nodejs24; also affects nodejs22-22.23.3). mock/COPR buildroots
  install with `install_weak_deps=0`, so the weak `nodejsNN-full-i18n`
  dependency is not pulled in automatically - which is why `%%check`
  segfaulted on COPR builders. The spec therefore hard-requires the
  version-agnostic `nodejs-full-i18n` provide at build and run time, and
  the `--help` check is fatal again. Reproduce with:
  `podman run --rm quay.io/fedora/fedora:rawhide bash -c 'dnf -y install
  --setopt=install_weak_deps=False nodejs22 && node -e \
  "new Intl.Segmenter().segment(\"x\")"'`

## Submitting to Fedora

The spec follows current guidelines (SPDX `License:`, vendored deps
documented per the Node.js guideline's prod/dev tarball pattern,
`%{zsh_completions_dir}`). For a real submission: request a package
review, import into dist-git (uploading Source0/1/2/3 to lookaside), and
switch `Release:` back to `%autorelease`. `rpmlint -r rpmlint.conf` is
clean.

If `nodejs-typescript` ever gets rebuilt in Fedora, the vendored compiler
can be replaced with `BuildRequires: nodejs-typescript` and dropping
`node_modules_dev/` from Source1.
